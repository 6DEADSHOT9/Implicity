# Kinds of chat are open per person and labelled by Hermes

Beyond five predefined kinds, new kinds are proposed by Hermes and accepted or renamed by the person, each inheriting from a predefined parent. Hermes labels each conversation, and the behaviour pipeline only ever receives the kind's id: a predefined kind name, or an opaque id the app mints when a custom kind is accepted, which survives renames. The label itself never reaches an event, because a label written by Hermes or the person could carry words from a message (amended by ADR 0020). A fixed list could not cover the range of work people do, and inferring kinds from structure alone could not name them. Reading the conversation is acceptable here because Hermes already reads it to answer.
