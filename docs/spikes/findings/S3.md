# S3: PostHog Endpoints API

**Result: PASS for API management and execution.** The self-hosted PostHog image supported endpoint creation, execution, update, version readback, and a date variable using a personal API key with endpoint read/write scopes. The initial Endpoint and regular query results matched.

## Calls that worked

All calls used `Authorization: Bearer <personal API key>` against project/environment `1`:

1. `POST /api/environments/1/endpoints/` with a named endpoint and a HogQL query that returns daily counts of placeholder `spike_query_event` grouped by the placeholder `kind` property. Response: `201`.
2. `POST /api/environments/1/endpoints/spike_daily_event_counts/run/` with `{}`. Response: `200`.
3. `POST /api/projects/1/query/` with the same query. Response: `200`; results matched the endpoint run.
4. `POST /api/environments/1/insight_variables/` with a String date variable. Response: `201`.
5. `PATCH /api/environments/1/endpoints/spike_daily_event_counts/` with the query referencing the returned variable `code_name`. Response: `200`; current version changed from 1 to 2.
6. `POST /api/environments/1/endpoints/spike_daily_event_counts/run/` with the date variable. Response: `200`.
7. `GET /api/environments/1/endpoints/spike_daily_event_counts/` returned version 2.

See [`s3-setup.json`](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s2-s3-posthog/spikes/s2-s3-posthog/s3-setup.json) for exact payloads and initial response timings.
