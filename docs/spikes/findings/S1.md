# S1 finding: Hermes to AI SDK UI stream

**Result: fail overall.** Responses passes the four content cases, but browser disconnect does not stop Hermes promptly. Runs stop and Chat Completions disconnect cancel separate turns, but do not preserve the complete Responses mapping. The session route streams text and structured tool inputs, and two turns in one session preserved context; it emitted no reasoning preview, and browser Cancel did not stop its turn (Hermes completed 88.2 seconds after the click). No tested route passes all S1 requirements.

## What Hermes sent

The installed Hermes HTTP API exposes authenticated OpenAI Responses streaming at `POST /v1/responses`. For the observed cases, the SSE stream contained `response.created`, `response.output_item.added` / `.done`, `response.output_text.delta` / `.done`, `response.reasoning_summary_text.delta` and related reasoning summary boundaries, then `response.completed`.

Tool interactions arrived as completed `function_call` and `function_call_output` output items. The tool item carried `call_id`, `name`, and JSON `arguments`; the result item carried that same `call_id` and an `output` array of `{type: "input_text", text: ...}` values. In these captures Hermes supplied full tool arguments in output-item events rather than argument delta events. Long replies arrived in many `response.output_text.delta` chunks. The reasoning case emitted a reasoning summary delta; this is the summary exposed by Hermes, not a full private chain of thought.

Evidence is in [plain.sse](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/plain.sse), [long.sse](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/long.sse), [reasoning.sse](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/reasoning.sse), [tool.sse](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/tool.sse), and [cancel-observation.txt](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/cancel-observation.txt), [cancel-follow-up.txt](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/cancel-follow-up.txt), and the additional stream captures below. The browser hook also rendered text, reasoning, a terminal call and its result as separate parts. The follow-up route tests are captured in [runs-cancel.sse](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/runs-cancel.sse), [runs-reasoning-observation.txt](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/runs-reasoning-observation.txt), and [chat-completions-cancel.sse](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/chat-completions-cancel.sse).

## Mapping

| Hermes Responses event | AI SDK UI Message part |
| --- | --- |
| `response.created` | `start` |
| assistant message output item added / done | `text-start` / `text-end` |
| `response.output_text.delta` | `text-delta` |
| reasoning output item added / done | `reasoning-start` / `reasoning-end` |
| `response.reasoning_summary_text.delta` | `reasoning-delta` |
| function call output item | `tool-input-start` then `tool-input-available` |
| function call output result item | `tool-output-available` |
| `response.completed` | `finish`, then `[DONE]` |

The relay marks responses with `x-vercel-ai-ui-message-stream: v1`. AI SDK's current UI Message Stream Protocol documents these SSE parts and the header: [Vercel AI SDK stream protocol](https://ai-sdk.dev/docs/ai-sdk-ui/stream-protocol). Hermes' current [API Server documentation](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server) documents Responses streaming, tool items, reasoning items, and the separate Runs stop endpoint.

## Lossy or awkward

- Hermes exposes reasoning summaries as `reasoning` parts; the prototype does not invent or recover private reasoning that Hermes does not send.
- Tool argument updates were not incremental in the captures. The relay emits the completed arguments as `tool-input-available` once Hermes closes the function-call item.
- Hermes tool outputs are content arrays, so the UI receives the output structure as-is rather than a simplified display string. Hermes can emit internal/denied tool calls as well as successful calls; the prototype renders both as tool parts and does not add a human approval flow.
- Browser `stop()` closes the relay's SSE response. The Responses writer batches text deltas on a background timer; a write failure there is logged by the timer task instead of reaching the main SSE loop's disconnect handler, so the agent continues until completion.
- Hermes source can emit a `reasoning.available` run event with a text preview capped at 500 characters, but the event was absent from the run tested with reasoning enabled. The current docs only say private reasoning does not appear as `message.interim`; they do not document this optional preview event.

## Cancel follow-up

### Route and source checks

- The installed API route table registers `POST /v1/responses`, `GET /v1/responses/{response_id}`, and `DELETE /v1/responses/{response_id}`. There is no Responses cancel route; `POST /v1/responses/{id}/cancel` returned HTTP 404. The request handler does not implement a Responses background mode.
- A Responses ID is not a Runs ID. `POST /v1/runs/{response_id}/stop` returned HTTP 404 with `run_not_found`. Source registers active run ownership and stop state for `/v1/runs`, not `/v1/responses`.
- The Responses SSE writer has a disconnect handler that calls `_abandon_agent_task`, but text deltas are emitted by `_ResponsesStream._batch_flush_after()` in a separate task. In this test, `ClientConnectionResetError` exceptions from that timer did not reach the request writer; it logged the disconnect only after the agent finished. No configuration flag or Responses background/cancel mode was found in the installed source or current API docs.
- `POST /v1/runs` returns its own `run_id`. For the same long-sailor prompt, `POST /v1/runs/{run_id}/stop` with `{}` returned `200 {"status":"stopping"}`. The stream ended with `run.cancelled`, and `GET /v1/runs/{run_id}` reported `cancelled` 214 ms after the stop request. This route passes cancellation, but its ID cannot stop a Responses turn.
- Run source can emit `reasoning.available` with up to 500 characters from `_relay_thinking`; this is a preview, not incremental reasoning deltas. A run explicitly requested with reasoning enabled at high effort emitted no `reasoning.available` event. The current docs state that private reasoning never becomes `message.interim`, but do not document this optional event. No setting was found that enables full or incremental reasoning deltas on Runs; `model_options.reasoning.enabled` requests generation but does not guarantee this preview event.
- `POST /v1/chat/completions` uses a direct SSE writer with a disconnect handler. An abort after 1,000 characters was followed by Hermes logging `SSE client disconnected; interrupted agent task`; `GET /v1/runs/{completion_id}` reported `cancelled`. Chat Completions also carries `reasoning_content`, but exposes tool progress events rather than structured function-call inputs and outputs, so it does not satisfy the tool-part case.
- `/api/sessions/{session_id}/chat/stream` has its own disconnect handler that drains and interrupts the live agent, and emits tool lifecycle events. It maps internal `reasoning.available` to `tool.progress` with a short `_thinking` preview. End-to-end results are in the session-route follow-up below.
- `hermes serve` is a separate JSON-RPC/WebSocket backend, not another HTTP Responses route. No version-specific cancellation note was found for the installed Hermes `0.22.5` source.

Exact calls, timings, statuses, and log evidence are in [cancel-follow-up.txt](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/cancel-follow-up.txt).

## Session route follow-up

**Result: partial pass; overall S1 remains fail.** The prototype created a session once per browser page with authenticated `POST /api/sessions` and `{"id":"<chatId>"}` (201, returning `session.id`). Each browser turn then posted `{"input":"..."}` to `POST /api/sessions/{session_id}/chat/stream`; the reasoning case also sent `model_options: {"reasoning":{"enabled":true,"effort":"high"}}`. The same `session_id` was reused for every turn in that page.

| Session SSE event | AI SDK UI part used in the prototype | Observation |
| --- | --- | --- |
| `message.started` | `text-start` | The relay assigns its own message ID. |
| `assistant.delta` | `text-delta` | Plain and long text rendered incrementally; the long case emitted 870 deltas over 74.6 seconds. |
| `assistant.completed` | `text-end` | Closes the text part after deltas. |
| `tool.progress` with `tool_name: "_thinking"` | `reasoning-start` / `reasoning-delta`; `reasoning-end` at `run.completed` | No such event appeared in the reasoning case, even with reasoning enabled at high effort; zero preview characters, no preview timing or increments to map. |
| `tool.started` | `tool-input-start`, then `tool-input-available` | Arguments arrived as a structured `args` object, not incremental argument deltas. The route omits a call ID, so the relay creates one. |
| `tool.completed` / `tool.failed` | Deferred until `run.completed`; matched by tool name and emitted as `tool-output-available` from the final tool message | These lifecycle events themselves contain only a preview and no result. The terminal `run.completed.messages` includes a tool-role result whose `content` is JSON text; the relay parses it into a structured output object. The output therefore arrives late, and matching relies on per-tool FIFO order. |
| `run.completed` | `tool-output-available` for tool-role messages, then `finish` and `[DONE]` | Carries final messages and usage; tool outputs are available only here. |
| `run.failed` / `run.cancelled` | `error`, then `finish` | Terminal error/cancel mapping. |
| `assistant.commentary`, `run.started`, `done` | Not mapped | Commentary and run metadata are not represented; final text is taken from deltas. |

The plain case rendered `SESSION-PLAIN-OK`. The long answer streamed in the browser and emitted 870 `assistant.delta` events. The reasoning case answered the probability question but emitted no `tool.progress` `_thinking` event. The tool case ran `printf 'SESSION-TOOL-RESULT-OK'`: `tool.started.args` was `{"command":"printf 'SESSION-TOOL-RESULT-OK'"}`; `tool.completed` had null `args` and `preview`; `run.completed.messages` contained `{"output":"SESSION-TOOL-RESULT-OK","exit_code":0,"error":null}`. The browser rendered that parsed output. Raw evidence: [session-plain.sse](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/session-plain.sse), [session-long.sse](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/session-long.sse), [session-reasoning.sse](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/session-reasoning.sse), and [session-tool.sse](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/session-tool.sse).

For the first cancel observation, the browser's Cancel click was recorded at `2026-11-24T12:03:38.973Z` (`17:33:38.973 IST`). The relay stopped capturing the connection at that point, but `GET /v1/runs/run_f6e33592541a43998da96f765fe37da2` still reported `running` at 17:34:30 IST. Hermes completed normally at 17:35:07.177 IST (98.1 seconds after request start, 88.2 seconds after Cancel), producing 23,715 characters. No `Session SSE client disconnected` or interruption log appeared. The capture ends at the browser disconnect and has no terminal SSE event: [session-cancel.sse](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/session-cancel.sse). This route's source contains a disconnect handler, but the browser relay did not make Hermes stop promptly in this observation.

Context passed in a clean page session: `POST /api/sessions` created session `4d8631c5-3622-4424-8b57-241fc05214c8`; its first turn asked Hermes to remember `ORBIT-741`, and a second turn on the same ID returned exactly `ORBIT-741`. Captures: [session-context-first.sse](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/session-context-first.sse) and [session-context-second.sse](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/session-context-second.sse). All five requested cases were exercised in the browser; the extra two-turn context check used a fresh browser session.

Exact calls, event observations, and cancellation log evidence are in [session-follow-up.txt](https://github.com/6DEADSHOT9/Implicity/blob/prototype/s1-ai-sdk-stream/spikes/s1-ai-sdk-stream/captures/session-follow-up.txt).
